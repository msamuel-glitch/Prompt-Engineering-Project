# Backend

The Python API of the application, built with FastAPI and Pydantic.

**Current state:** a course file (PDF or PPTX) can be uploaded to get a study
sheet generated by Claude, with the pages or slides each section comes from and
automatic checks on those references. Sheets are not saved yet.

## Setup

Requires Python 3.11 or later. From this `backend/` folder:

```bash
# Create a virtual environment (macOS/Linux: python3 -m venv .venv)
py -3 -m venv .venv

# Activate it
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Windows Git Bash:   source .venv/Scripts/activate
# macOS/Linux:        source .venv/bin/activate

# Install the application and test dependencies
pip install -r requirements-dev.txt
```

If PowerShell refuses to run the activation script, skip activation and prefix
the commands with the environment's Python, for example
`.venv\Scripts\python -m pytest`.

## Configuration

Copy `.env.example` to `.env` in this folder and fill it in. `.env` is ignored by
Git: never commit it.

| Variable | Default | Purpose |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | none | Key used to call Claude. Create it with a spending limit. |
| `STUDY_SHEET_GENERATOR` | `claude` | `fake` builds a placeholder sheet from the course text, with no AI call and no cost. Useful to work on the interface. |
| `CLAUDE_MODEL` | `claude-opus-5-5` | Model that writes the sheets. `claude-sonnet-5-5` costs half as much; compare them with the evaluation before switching. |
| `STUDY_SHEET_PROMPT_VERSION` | `v2` | Prompt file used from `prompts/study-sheet/`. It must ask for the structured output of `app/schemas.py`. |

The backend reads `.env` when it starts: restart it after changing the file
(`--reload` only watches Python files). Without a key and with the `claude`
generator, uploads return an error that explains what to set.

## Run

```bash
uvicorn app.main:app --reload
```

The API listens on http://127.0.0.1:8000. The interactive documentation generated
by FastAPI is at http://127.0.0.1:8000/docs, where each route can be tried.

| Route | Purpose |
| --- | --- |
| `GET /api/health` | Returns `{"status":"ok"}` when the API runs |
| `POST /api/sheets` | Takes a course file (`file`, PDF or PPTX, up to 30 MB) and returns a study sheet |

## How a sheet is made

1. `extraction.py` reads the text of each page (pdfplumber) or slide
   (python-pptx). Files without any text, such as scanned PDFs, are rejected:
   text recognition is not supported.
2. The text is put under `[Page N]` or `[Slide N]` markers and inserted into the
   prompt read from `prompts/study-sheet/` (`prompts.py`).
3. `generation.py` sends it to Claude with the `StudySheet` schema as structured
   output, so the answer is validated data rather than free text.
4. `checks.py` flags sections that cite pages missing from the file or without
   text, sections without a source, and sheets over 900 words. These warnings
   are shown to the student; they do not prove that a cited page supports its
   section.

Courses longer than 300,000 characters are refused to bound the cost of a
request; the strategy for long courses is still an open decision.

## Test

```bash
pytest
```

The tests never call the Claude API: they build small PDF and PPTX files and
replace the API with fakes, including a fake network layer under the real SDK.

## Structure

| Path | Content |
| --- | --- |
| `app/main.py` | FastAPI application and health route |
| `app/sheets.py` | Upload route and choice of generator |
| `app/extraction.py` | Text extraction from PDF and PPTX files |
| `app/prompts.py` | Loading of the versioned prompts |
| `app/generation.py` | Claude and placeholder generators |
| `app/checks.py` | Automatic checks on generated sheets |
| `app/schemas.py` | Pydantic data contracts, also sent to Claude as the output schema |
| `app/config.py` | Settings from environment variables and `.env` |
| `tests/` | Tests, run with pytest |
| `requirements.txt` | Runtime dependencies, pinned |
| `requirements-dev.txt` | Runtime plus test dependencies |
| `pyproject.toml` | pytest configuration |

All routes start with `/api`, so the frontend development server can forward
them to this API. After changing `app/schemas.py`, regenerate the frontend types
(see the [frontend README](../frontend/README.md)).

## Dependencies

`requirements.txt` pins every runtime package so that all team members install
the same versions. To add a dependency, install it in the virtual environment,
check that the tests still pass, then regenerate the pinned list from a clean
environment with `pip freeze`. Add packages when the feature that needs them is
implemented.

## Planned responsibilities

- Study-sheet persistence, edit history or original AI versions, and the subject
  library in SQLite.
- Flashcard and quiz generation, plus scoring based on the agreed contract.

Keep API credentials on the server. Local uploads, exports and databases are
ignored by Git. Reusable prompt text belongs in the root prompts/ directory.
